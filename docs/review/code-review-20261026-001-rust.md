## 二、功能评估

### 2.1 定量结果

232 页中 **90 页输出发生变化**（38.8%），其中：

| 类别 | 页数 | 说明 |
|------|------|------|
| 明显改善 | 约 30 页 | 基线把表格拆成单列流水/重复单元格，重建后成为对齐矩阵 |
| 轻微变化 | 约 50 页 | 空行、缩进、页脚页码纳入、目录空格收敛 |
| 严重劣化 | **7 页** | 193/197/199/202/207/216/219，整页塌成 1~2 行巨长字符串（最长 778 字符） |
| 内容丢失 | 0 页 | 字符多重集差分仅 1 页（127）有差异，核对后是基线重复绘制，非丢失 |

### 2.2 收益（真实且显著）

1. **表格还原正确**：页 58（VaR 放大倍数表）、136（ABS 风险权重矩阵）、143（β 系数表）、156、213（产品线对应表）等重建为列对齐网格，`rowspan` 单元格如实留空（绿区/黄区/红区），基线此处是「区域/数量/倍数 三类内容各自成段」的碎片。
2. **顺带修好了阅读顺序**：页 118/126/180/183 基线把脚注正文与段落交替输出、句子被切成两半；坐标路径按行带聚类后恢复为「正文 → 脚注在页末」，这是本次改动未被宣传但价值更高的副作用。
3. **去除了重复绘制**：页 136 基线出现 `650% / 扣减` 的重复行，坐标路径因按词去重而消失。
4. **工程实现符合项目既定约束**：纯函数式管线（`group_rows → detect_table_regions → render_region`）、零新增依赖、检出失败返回 `None` 回退基线、单页失败只 `warn` 不拖垮整篇，与「只还原不推断」「不静默降级」一致。

### 2.3 代价与风险

1. **旋转（横向）页彻底崩坏**：这是唯一的功能性硬伤。该 PDF 中 21 页为 90° 旋转的横向附录表（193~208、216~220），其中 7 页被检出「表格」后整页重建。旋转后词包围盒的高宽互换，行聚类把「视觉列」当成「视觉行」，输出成一整行 490~778 字符的巨串，并夹杂数百个空格填充，**可读性低于基线**（基线至少是按词纵向排列的列表）。示例（页 193 实际输出，节选）：

```
IRB 期限:违约损失率:资产类别:2.5年        公司贷款45%50 45%5      45%住房抵押贷款法风险权重的实例25% 45%其他零售贷款85%    ...
```

2. **整页重建而非仅替换表格区域**：`rebuild_page` 对检出表格的页用坐标流重写整页（含正文），因此「表格页的正文排序」也一并交给本模块的启发式。本样本中该启发式恰好优于基线，但这是**版式运气**，不是设计保证；换一种版式（多栏+浮动框+表格共存）就可能出现正文错序。模块文档只声明「非表格页零回归」，未声明「表格页正文会被重新排序」，认知上容易误判风险面。
3. **一个区域容纳两张不同列表时列槽位串味**：页 127 的「长期评级」表与「短期评级」表紧邻、列数不同，被合成一个区域，槽位由前者塑形，后者表头 `短期评级种类` 被塞进第 2 列，数值行错位。
4. **2 行的「表格」不还原**：`MIN_TABLE_ROWS = 3` 让页 36 的两张 2 行表（信用评级/风险权重）保持基线碎片状态。这是刻意的防误判取舍，页 36 输出与基线逐字符一致（无回归），但用户视角仍是「表格没修好」，需在文档中明确该边界。

### 2.4 功能评分

| 维度 | 评价 |
|------|------|
| 方向正确性 | 高。只消费最底层词包围盒、聚类自持，符合项目「把控制权拿回来」的既定决策 |
| 主流版式收益 | 高。纵向正文页的表格还原与阅读顺序均有可验证改善 |
| 鲁棒性 | **不合格**。旋转页 100% 崩坏，且无任何自检兜底 |
| 可测性 | 中。12 项单元测试质量不错（阈值边界、上标归行、右对齐槽位、正文不误判），但缺端到端用例，旋转页这类问题单元测试结构上就测不到 |
| 文档一致性 | 中。算法与阈值注释带实测数据，质量高于项目平均；但存在失联引用（`CELL_GAP`）与风险面描述不全 |
| 性能 | 好。无可观测退化 |

**结论：功能有价值，但当前状态不可合入。** 必须先解决旋转页崩坏（P0），再补端到端回归测试（P1）；其余为应当修正/建议改进。

## 三、问题清单

### 必须修正（优先级：高）

#### P0-1 旋转页重建产出一行巨串，可读性劣于基线

- **位置**：`src/converter/pdf.rs:90-120`（`rebuild_page_text` 只取 `word.bbox`）、`src/converter/pdf_table.rs:158`（`group_rows`）
- **现象**：90° 旋转的横向表（本样本 21 页中的 7 页）被整页重建后塌成 1~2 行，最长 778 字符，夹杂数百空格。
- **成因**：坐标路径假设「y 轴向上、文本水平」。旋转文本的包围盒高宽互换（实测 `IRB` 18.2×18.2、8 个汉字 96.4×96.5），行聚类把视觉列当行。
- **修复建议**（二选一，建议先做 A）：
  - **A. 检测即回退**：`pdf_oxide` 的 `Word`（`TextBlock`）带 `chars: Vec<TextChar>`，`TextChar.rotation_degrees` 直接给出 0/90/180/270。转换 `PlacedWord` 时统计主旋转角，非 0 度即整页返回基线；退一步也可用几何判据 `h > 2.0 * fs`（本样本 21 个旋转页该比例均 ≥0.85，正文页为 0），无需依赖底层字段。
  - **B. 真正支持旋转页**：按主旋转角对坐标做逆变换后再聚类，输出按旋转后版式排布。成本高，且旋转页多为横向大表，建议单独立项。
- **验收**：`samples/demo2.pdf` 页 193~208、216~220 的输出不含长度 >200 的行，且与基线逐页相似度不低于 0.95（应几乎等于基线）。

#### P0-2 渲染缺少「输出合理性」兜底

- **位置**：`src/converter/pdf_table.rs:375`（`render_region`）、`457`（`rebuild_page`）
- **问题**：列宽取「全区域内最大单元格显示宽度」，无上限；一旦槽位塑形失败（如 P0-1），填充空格可达数百列，且没有任何自检发现「这页明显坏了」。
- **建议**：`rebuild_page` 渲染完做一次廉价校验——最大行宽超过阈值（如 200 显示列）或空格填充占比异常即返回 `None` 回退基线；同时给列宽加合理上限（超过则按列截断宽度、不阻断内容）。这类兜底与项目「不静默降级」并不冲突：降级有日志、结果仍完整。

### 应当修正（优先级：中）

#### P1-1 表格路径零端到端测试，新增样本未被任何测试使用

- **位置**：`tests/convert.rs`（未改动）、`samples/demo2.pdf`（新增 756K，无引用）
- **问题**：新路径的全部覆盖来自 `pdf_table` 内的合成词表；`pdf.rs` 的页切分/回退/串联逻辑、以及与真实 PDF 词坐标的契约（`extract_all_text` 分段数 == `page_count`、旋转文本、真表格）完全无测试。P0-1 这类问题只要有一条「真实 PDF 页 → 期望网格」的用例就会被拦住。
- **建议**：在 `tests/convert.rs` 增加两项——(a) 对 `samples/demo2.pdf` 指定页断言表格列对齐（如页 136 的 `BBB+ 50% 50% 50%` 同一行、列起始位置一致）；(b) 对旋转页断言输出不含超长行。样本已在仓库内，成本仅是运行时增加。
- **附带**：`samples/demo2.pdf` 756K 进仓库却无人使用，属于「只增负担不增保障」，补测试后才有意义。

#### P1-2 同一区域容纳多张不同列表时列槽位串味

- **位置**：`src/converter/pdf_table.rs:302`（`build_column_slots`）、`210`（`detect_table_regions`）
- **现象**：页 127 两张紧邻表格（长期评级 5 列、短期评级 4 列）合并为一个区域，后表表头被塞入前表槽位，`350%` / `扣减` 与表头错位。
- **成因**：区域链只判断「行是否有列间隙 + 与前行对齐」，表头的列结构变化不打断链；槽位塑形取区域内全部多词行的并集。
- **建议**：在链内按「列锚点集合变化」切分子块——相邻行对齐命中的锚点集合与当前子块差异超过一半即开新子块，各自塑形槽位；或退一步，当日志可观测到某区域行数/列数突变时降级该页。至少要给出可复现用例并把该场景写进「边界」小节。

#### P1-3 文档声明与行为不一致

- **位置**：`src/converter/pdf_table.rs:452-456`、模块文档「边界」段
- **问题**：`rebuild_page` 文档写「非表格行按词间隙拼接（间隙 ≥ [`CELL_GAP`] 补一个空格）」，但常量 `CELL_GAP` 不存在（现为 `GAP_RATIO_TIGHT` 比例判定）；同时「边界」只声明非表格页零回归，未声明**表格页的整页正文也会被坐标流重排**，而正文排序完全依赖行聚类。
- **建议**：修正失联引用；在「边界」补一条「检出表格的页整页由坐标流重建，正文排序亦由行聚类决定，多栏/浮动框版式存在正文错序风险」。这条直接影响后续维护者对该模块回归面的判断，值得写清楚。

### 建议改进（优先级：低）

#### P2-1 页脚页码进入输出，属未声明的行为变更

- 90 页中有多页在末尾多出印刷页码（如页 213 末尾 `211`、页 118 末尾 `116`），基线不输出。对下游无实质影响，甚至更有用，但属于行为变更，建议在 README/CHANGELOG 与 SKILL.md 的能力表中记一句（README 目前只写了「表格按坐标重建」）。

#### P2-2 数字列判定内置了中文内容词

- **位置**：`src/converter/pdf_table.rs:322`（`is_numeric_column`）
- **问题**：为命中 `200 及 200 以上`，白名单里硬编码了 `至/及/以/上/无`。语义上这是「单位词」而非「数字字符」，换一种表述（`200以上(含)`、`≤200`、全角括号）即失效，且会让含这些字的文本列被误判为数字列而右对齐。
- **建议**：改为「剥离数字/符号后仅剩有限单位词」的判定，或收敛为 `以上/以下/至/及` 之外的字符一律非数字列；至少把白名单的来源（该 PDF 的三种句式）写进注释，避免后人以为是通用规则。

#### P2-3 渲染阶段的重复克隆

- **位置**：`src/converter/pdf_table.rs:416-428`
- **问题**：`is_numeric_column` 每列把 `cells[col]` 完整 clone 成 `Vec<String>`，随后又遍历一遍算宽度。区域行数上百时是无谓分配。
- **建议**：直接借用 `&str` 迭代（`grid.iter().map(|c| c[col].as_str())`），签名改 `&[&str]`。属微优化，顺手可改。

#### P2-4 阈值全部为全局常量，缺少按样本的可调入口

- 5 个阈值（`GAP_FOR_TABLE` / `COL_TOL` / `SLOT_MERGE_GAP` / `MIN_TABLE_ROWS` / `ROW_PROXIMITY`）注释都带实测依据，质量不错；但它们针对「中文 A4 正文 + 表格」这一种版式。若后续接入英文/双栏/窄栏文档，没有配置或按页自适应入口，只能改代码重编译。建议至少把「阈值 + 依据」集中成一个 `LayoutProfile` 结构，为多版式留出入口（不必现在实现多套）。

## 四、优秀设计（值得保留）

1. **两级回退语义**：整篇基线失败 → 报错；单页坐标抽取失败 → warn + 本页基线；页内未检出表格 → 基线。失败面逐层收缩，符合「不静默降级」（有日志、有完整结果）。
2. **注释带实测数据**：`GAP_RATIO_TIGHT = 0.26` 的来源写清了「CJK 词内 0.22~0.26 × 字高、英文 fs12 空格 0.28 倍、fs9 仅 ~0.25pt」——这正是上一版固定 4pt 阈值导致 `havemultipleinterfaces` 粘连的原因，注释把踩坑过程固定下来了。
3. **测试选型准确**：`distant_prose_row_stays_out_of_table`、`superscript_joins_body_row`、`right_aligned_numbers_share_slot` 三条都对准了算法最脆的两个环节（区域越界、上标归行、右对齐漂移），不是凑数的 happy path。
4. **`needs_space` 用「间隙/字高 + 边界字符类型」替代绝对距离**，是本模块最见功力的一处：中英文之间不存在安全的固定距离，这个结论有数据支撑。

## 五、总结

方向与实现质量都在项目平均线之上：单文件 820 行、职责单一、阈值有实测依据、失败有回退、无新依赖、性能无退化；在一个 232 页真实文档上把表格还原和阅读顺序同时修好，收益是实的。

但**旋转页的崩坏是硬伤**：21 个旋转页中 7 页输出退化为一行数百字符的乱码，比基线更差，且现有测试结构完全测不到。合入前必须完成 P0-1（旋转检测回退）与 P0-2（输出合理性兜底），并补 P1-1 的端到端用例；P1-2/P1-3 建议同批处理，避免「多表混区」和「文档风险面失真」两笔债留给下一个改这块的人。
