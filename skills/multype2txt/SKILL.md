# multype2txt 文档转文本技能

## 作用

调用本地命令 `multype2txt`，把 Office 与 PDF 文档转换为对应格式的文本。

- 转换在本地完成，**不消耗任何 token**：模型不需要读取二进制内容，也不需要请求
  外部服务。
- 转换结果写入 stdout 或文件；模型按需只读取其中需要的那一段，进一步节省上下文。
- 覆盖格式：`doc` `docx` `ppt` `pptx` `xls` `xlsx` `pdf`。

## 默认输出格式

按输入类型自动选择，可用 `-f` 覆盖：

| 输入 | 默认输出 | 说明 |
|------|----------|------|
| `docx` | Markdown | 标题、列表、表格、超链接保留为 Markdown 语法 |
| `doc` | Markdown | **尽力支持**，结构明显弱于 docx，见下节 |
| `xls` `xlsx` | CSV | **全量**单元格数据，多工作表以 `# sheet:` 注释行分隔 |
| `pptx` | Markdown | 幻灯片页、标题、列表层级、演讲者备注，页间以 `---` 分隔 |
| `ppt` | Markdown | **尽力支持**：页与标题保留，列表层级全部丢失 |
| `pdf` | 纯文本 | 阅读顺序正文 + 表格按坐标重建为对齐网格，`-f markdown/csv` 会直接报错；结构还原不理想时用 `--pdf-tables=off` 退回线性文本（见 [PDF 表格重建](#pdf-表格重建何时有用何时该关)） |

## 转换 legacy 格式后，务必提示使用者

`doc` / `ppt` 是二进制流式格式，底层只抽得出文字流，不解析粗体、编号、列表层级、
表格与图片位置，结构靠逐行启发式重建。实测同一份内容：

| 输入 | 结构行（标题+列表） |
|------|--------------------|
| `demo.doc` | 1 |
| `demo.docx` | 41 |
| `demo.ppt` | 26（无列表） |
| `demo.pptx` | 38 |

**因此每次转换 `doc` / `ppt` 之后，都应当主动告知使用者结果不完整**，例如：

> 已转换 `旧文档.doc`。注意：`.doc` 是二进制格式，本次只能抽出文字与大致标题，
> 原文档的列表层级、表格结构、粗体与图片位置全部丢失。若结构对后续分析重要，
> 建议先另存为 `.docx` 再转换（或用 LibreOffice 批量转换）：
>
> ```bash
> libreoffice --headless --convert-to docx --outdir out/ legacy.doc
> multype2txt -i out/legacy.docx -o legacy.md
> ```

不要把 `doc` / `ppt` 的输出当作完整结构使用——它看起来像 Markdown，但层级是猜的。
`xls` 的**结构**不受此影响（CSV 走原生网格读取，行列仍全量对齐），但它有另一类
缺陷——输出乱码，见下节。

## 转换 xls 出现乱码时，务必提示使用者

`.xls` 的共享字符串表可能被 `CONTINUE` 记录切开，底层解析在边界处错位，把编码
标志字节当成字符读入，其后所有偏移全部错乱。实测 `demo.xls`（65562 行）：
**第 51~80 行混入 82134 个控制字符（含 76215 个 NUL）**，终端里表现为乱码；
`-f text` 走 IR 路径同样中招——这是解析层缺陷，与输出格式无关。

**检测**：转换后若看到 `\x00`、`\x01`、成片的方块/问号，或 `h\x00t\x00t\x00p`
这类半截字符，即命中该缺陷。输出仍是合法 UTF-8，但那些行的内容已经错位。

**处理**：不要把乱码行当作数据使用，先转 `.xlsx` 再转换（OOXML 走 XML 解析路径，
不受影响，实测控制字符为 0）：

```bash
libreoffice --headless --convert-to xlsx --outdir out/ dirty.xls
multype2txt -i out/dirty.xlsx -f csv
```

该缺陷在底层 `office_oxide` 0.1.12+ 已修复，但配套的 `pdf_oxide` 尚未适配其
IR 变更，暂时无法靠升级依赖解决，因此只能绕开 `.xls` 这个格式。

## PDF 表格重建：何时有用、何时该关

PDF 没有结构语义，表格是**按词坐标几何重建**的：行 = 垂直投影重叠；表格行 =
行内存在 ≥1 em 的列间空白；列 = 多数行（≥60%）留空、宽度 ≥1 em 的垂直空白带；
对齐方式复制原文档（右边缘比左边缘稳即右对齐）。判据全部无量纲（em 倍数、
行占比、行数），没有为某份文档试出来的 point 阈值。重建结果还要过自检：字符
守恒、行宽不超过物理上界、不得比基线少字，任何一条不过就整页回退基线文本。

这套判据在**短数值表**上稳定，在**长文本表**上会整并列，在**图/幻灯片**上会
把标签框当多列结构。以下是 11 份文档与 `pdftotext` 对拍后的结论（9 份外部
PDF + 2 份样本）：

| 文档类型 | 建议 | 实测依据 |
|----------|------|----------|
| 中文正文 / 中文表格（监管文件、手册、研报） | **优先本工具** | CJK 兼容字形归一为正常汉字（`⼀`→`一`、`⻚`→`页`），可搜索可复制；表格成列对齐；正文与 pdftotext 逐段一致 |
| 英文监管**短表** | 本工具略优 | 数值/权重表对齐，正文一致 |
| 英文监管**长文本表**（意见反馈、定性披露） | `pdftotext -layout` 更干净 | 单元格文字换行后跨越列界，多数行都"有词跨越"，相邻两列被整并，出现 `not abletospecifiesprovide an` 这类交错 |
| 英文论文 / 公式密集 | `pdftotext -layout` | 公式上下标两边都还原不了，但 -layout 的留白更接近原版面 |
| 幻灯片 / 海报 | 海报平手，幻灯片 `-layout` 略优 | 版面文字框散布，重排后行内片段交错；`/Rotate` 幻灯片可能出现词粘连（`UniversityZurich`） |

### 退化信号：转换后自查

做法很简单：同一份 PDF 跑两遍（默认与 `--pdf-tables=off`）再对比。下面两段
命令分别给出「重建改了什么」与两个客观指标，命中任意一条就改用 `off` 版：

```bash
# 只看重建改动了哪些页、改成了什么样：两边都跑一遍做 diff
multype2txt -i report.pdf -o on.txt
multype2txt --pdf-tables=off -i report.pdf -o off.txt
diff off.txt on.txt | head -60

# 1. 粘连词：≥20 个连续字母且不是技术术语（正常英文不会这么长）
grep -oE '[A-Za-z]{20,}' on.txt | sort | uniq -c | sort -rn | head

# 2. 目录：标题与页码分离、点线引导（......）整段消失（与 off.txt 对比）
grep -c '\.\.\.\.' off.txt on.txt
```

判读：

- `diff` 里看到「同一行被塞进两段互不相连的句子」（尤其是 4 列以上的意见
  反馈表、定性披露表）→ 列被整并，改用 `off.txt`；
- `grep` 出现非技术术语的长粘连串（如 `abletospecifies`、`UniversityZurich`）
  → 空格判据在旋转页失效，改用 `off.txt`；
- 目录点线数在 `on.txt` 明显变少甚至为 0 → 目录页被按正文重排，改用 `off.txt`；
- 以上都没有，且表格成列对齐 → 用默认输出（`on.txt`）。

处置：

```bash
multype2txt --pdf-tables=off -i report.pdf -o report.txt
```

### 已知边界（不影响正确性，但影响可读性）

- **长文本多列表列间整并**：当前最主要的弱点，纯文本消费时需人工核对列归属；
- **`/Rotate` 页把整列数值画成一个文本段**：库给出的包围盒是整段并集，个别
  数值可能落到相邻行（内容不丢，位置可能偏）；
- **跨页表格不拼接**：两页各自对齐，不做推断性拼接；
- **双栏正文会按两列网格还原**：版式忠实，但线性阅读不如单栏文本；
- **示意图的标签框**可能被当作多列结构重排；
- **页眉/页脚/水印**：库把它们当 artifact 丢弃，`pdftotext` 会保留——差异出现在
  这些行时不是内容丢失。

## 为什么不直接读取文档

`.docx/.xlsx/.pptx/.pdf` 等是二进制或压缩包格式，直接读取会得到乱码或极长噪声，
既浪费 token 也无法理解。正确做法是先用本技能转换，再读取文本。

对 xlsx 尤其重要：原文件动辄数百万字符的二进制噪声，转换成 CSV 后才能被直接理解。

## 定位可执行文件

按以下顺序选择其一：

1. 已在 PATH 中：直接使用 `multype2txt`。
2. 在本仓库内：先构建，再使用产物路径。
   ```bash
   cargo build --release
   ./target/release/multype2txt --help
   ```
3. 长期使用可安装到用户目录：
   ```bash
   cargo install --path .
   # 或
   cp target/release/multype2txt ~/.local/bin/
   ```

## 用法

```text
multype2txt -i <输入文件> [-o <输出文件>] [-f <格式>] [--images-dir <目录>] [-v|-vv]
```

| 参数 | 说明 |
|------|------|
| `-i, --input <FILE>` | 必填。输入文档路径。 |
| `-o, --output <FILE>` | 可选。输出文件路径；缺省写入标准输出。 |
| `-f, --format <FMT>` | 可选。`auto`（默认）/ `markdown` / `csv` / `text`。 |
| `--images-dir <DIR>` | 可选。把图片字节导出到该目录，占位符指向实际文件。对 Markdown 输出（`docx`/`pptx`）与 PDF 有效；对 `doc`/`ppt` 不生效，对 CSV 输出报错。 |
| `--pdf-tables <MODE>` | 可选，仅对 PDF。`auto`（默认）按坐标重建表格；`off` 关闭重建，输出与引入该功能前逐字节一致的线性文本。 |
| `-v, --verbose` | 可选。诊断日志额外输出到 stderr（`-v`=info，`-vv`=debug）；默认只写日志文件。 |
| `-h, --help` / `-V, --version` | 帮助 / 版本。 |

### 基本示例

```bash
# docx 输出 Markdown（适合直接交给模型阅读，保留标题与层级）
multype2txt -i report.docx

# xlsx 输出 CSV 到文件，后续反复读取不再重复转换
multype2txt -i sheet.xlsx -o sheet.csv

# 退回纯文本（只要正文、不要结构时）
multype2txt -f text -i report.docx -o report.txt

# 输出到 stdout 并只取前一段，节省上下文
multype2txt -i report.pdf | head -n 100

# PDF 表格重建结果不理想时（长文本表、公式页、幻灯片），退回线性文本重跑
multype2txt --pdf-tables=off -i report.pdf -o report.txt

# 需要看图时把图片字节另存，占位符会指向真实文件
multype2txt --images-dir report-imgs -i report.docx -o report.md

# PDF 也可导出图片，占位符追加在对应页末尾（页边界不变）
multype2txt --images-dir report-imgs -i report.pdf -o report.txt

# 批量转换整个目录
for f in docs/*.docx docs/*.pdf; do
    multype2txt -i "$f" -o "${f%.*}.md"
done
```

## 推荐工作流

1. 判断输入是否为二进制文档格式；是则使用本技能，不要直接读取原文。
2. 小文件可直接输出到 stdout 并读取；大文件建议先 `-o` 落盘。
3. 对落盘的文本再用检索/分段读取，只把需要的片段带入上下文。
4. xlsx 走 CSV 后**不要在转换环节做裁剪**：略读、采样、摘要是你的职责，
   转换器只负责把数据完整交出来。
5. 批量处理时用循环逐一转换，避免单个文档占用过多上下文。
6. PDF 转换后先看三条退化信号（粘连词、表格行内交错、目录点线丢失）；
   命中就 `--pdf-tables=off` 重跑，再决定用哪一版。

## 输出约定

- 转换结果只出现在 stdout（或 `-o` 文件）中。
- 诊断日志默认只写 `/tmp/<输入文件名>.conv.err.log`：没有警告或错误就不生成该
  文件；有问题时 stderr 会在输出结束后打一行提示给出路径。加 `-v` 则日志同时
  显示在 stderr，便于排查。
- 该命令不读取 `RUST_LOG`，外部环境变量不会导致日志混入数据。
- PDF 按页面阅读顺序抽取正文，页与页之间以换行符 `U+000C`（`\f`）分隔，
  用于保留分页边界，不产生可见的标记文本。
- CSV 中以 `#` 开头的行是元信息（工作表名、行列数、合并区域），**不是数据**；
  严格的 CSV 解析器需跳过这些行。

## 图片处理

**本工具不解析图片内容，这是明确的能力边界。**

- Markdown 输出中，图片表现为占位符 `![图片1: 系统架构图](image://1)`：
  有描述时填入描述，无描述时只有编号。
- 需要真实图片时加 `--images-dir`，字节会落盘，占位符 URL 指向实际文件，
  由你自行决定是否读取。
- **PDF 也支持 `--images-dir`**：按页抽图落盘，占位符追加在**该页正文末尾**
  （页边界不变，仍是 `\f` 分隔）。PDF 图片没有描述文字，占位符只有编号。
  遇到底层解不开的图，会在该页末尾留下 `[图片N 导出失败: 原因]` 而非静默丢弃——
  见到这种行时，应告知使用者该图未能导出，而不是当作没有图。
- Excel 输出中图片完全忽略、不留占位符；PPT 图表数据同样不导出（属于「图」）。
- `doc` / `ppt` 的图片**不会**导出，也不报错：底层能抽出字节，但正文里没有
  位置可挂占位符，强行导出只会留下无人引用的孤儿文件。

## 退出码

| 退出码 | 含义 | 处理建议 |
|--------|------|----------|
| `0` | 转换成功，或下游提前关闭管道（`\| head`） | 继续后续处理 |
| `1` | 转换失败 | 检查文件是否存在、格式是否受支持、输入输出格式是否兼容、是否损坏；加 `-v` 查看原因 |
| `2` | 命令行参数错误 | 检查 `-i/-o/-f` 参数 |

## 注意事项

- 不支持的格式：`xlsb`、`csv`、`txt`、`rtf`、`odt` 等会返回退出码 1。
  txt 本身已是文本，无需转换。
  - `xlsb` 暂不支持是刻意的：依赖的 `rxlsb` 存在列错位与公式值丢失缺陷，
    在修复前宁可拒绝也不产出错位的数据。
- 请求了输入无法提供的格式会直接失败（例如对 PDF 要 CSV、对文档要 CSV），
  报错信息会说明原因——这是刻意设计，避免拿到「看起来像、其实不是」的数据。
- **转换 `doc` / `ppt` 后必须提示使用者结果不完整**，并给出「先转 `docx`/`pptx`」
  的建议，详见 [转换 legacy 格式后，务必提示使用者](#转换-legacy-格式后务必提示使用者)。
- **转换 `xls` 后若发现乱码，必须提示使用者先转 `xlsx`**，详见
  [转换 xls 出现乱码时，务必提示使用者](#转换-xls-出现乱码时务必提示使用者)。
- **PDF 表格重建是启发式的**：中文文档通常更好；长文本表、公式论文、幻灯片
  可能不如 `pdftotext -layout`。转换后先按
  [退化信号](#退化信号转换后自查) 自查，必要时用 `--pdf-tables=off` 重跑。
- `--images-dir` 对 `doc` / `ppt` 不生效（不导出也不报错）；对 PDF 生效，
  但内联图可能解码失败并留下 `[图片N 导出失败: …]` 标注。
- 加密（受密码保护）的 OOXML 文档不支持解密，会明确报错。
- 扩展名大小写不敏感；工具会结合文件头签名识别真实格式，扩展名写错多可容忍。
- 不要把 `-o` 的文件名与输入放在同一路径覆盖源文件；如需保留原件，输出到不同目录。
- 图片文件按 `img-0001.png` 顺序编号，**建议每个文档使用独立的 `--images-dir`**，
  复用同一目录会覆盖同名文件。

## 排障

```bash
# 查看帮助
multype2txt --help

# 打开诊断日志定位失败原因
multype2txt -v -i broken.pdf -o out.txt

# 确认版本
multype2txt --version

# 想确认输出格式映射是否符合预期
multype2txt -f markdown -i sheet.xlsx | head -n 20
```
